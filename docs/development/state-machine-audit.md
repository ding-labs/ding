# Ding state-machine audit

Audited the shipping app at `1fd739c` and the changes on this branch. The watch store owns watch transitions. Inspecting a watch now returns a snapshot of actions available to the inspecting caller. The Console and MCP clients use that snapshot. A write still checks the latest generation, permissions and transfer hold inside the transaction.

## Qualification and limits

- The pilot adds optional `lifecycle.actions`, `reason` and `transferId` to detail results. Ordinary management, integration grants, narrower OAuth tokens, transfer holds, unknown states and old/new schemas have executable checks. The API rechecks writes against current state. List reads keep their existing query paths. No database migration is required.
- A local upgrade rehearsal built the CLI/daemon from the `v0.15.2` tag, created a push watch, recorded a firing and a completed delivery, and paused it. The current daemon reopened that state. Pre-existing watch, entity and delivery fields compared equal, the existing migration supplied a watch lifetime, and both released and current CLIs inspected the result. The current CLI also inspected the released daemon while it was running.
- SQLite and PostgreSQL use an indexed join against the single held transfer when loading a watch detail. For a personal non-log watch the detail still issues three data SELECTs for the watch, entities and deliveries, plus backend transaction setup. Logs also read the latest log observation. The existing shared-workspace authorization rule can read credential-bearing source metadata for a restricted manager. Modern Console detail skips workspace-wide transfer polling and reads a single transfer only when held. The legacy Console fallback still works with a server that omits guidance.
- Existing users may have local transfer histories created by an earlier build that only recorded the most recent test key. That active key remains readable. Starting with this change, replacing a key retains its superseded identity within the existing bounded handoff record. An older key already overwritten before this change cannot be reconstructed.
- Automated tests exercise transport acknowledgment loss, generation and role changes, receipt replay, rollback, restart, both storage backends and browser recovery. Native notification prompts, service-manager UX on other operating systems, live identity-provider consent and real external notification receipt require their respective environments. The stdin/NDJSON and followed-file/metrics 24-hour soaks remain optional background checks, independent of delivery.

The tagged Go suite passed with the race detector, and `go vet` passed. Eight focused runtime cases also ran on an isolated PostgreSQL database. The Console passed 64 unit cases, with 8 more in the MCP widget. All three browsers passed 40 Console journeys each, with two opt-in cases skipped per browser. Firefox ran in the Linux qualification image because native macOS Firefox could not create its test profile. After the final apply-response check, the affected journeys passed again in all three browsers. The independent MCP SDK exercised 20 tools, both MCP browser journeys passed, and the public website/install tests passed eight cases.
