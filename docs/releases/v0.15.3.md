# Ding 0.15.3

Notifications now use matching Ding bells: yellow for warnings, red for failures,
and green when a watch or its observation source recovers. Each includes a text
status label as well as the colored artwork.

Slack displays the bell inside the message. Discord uses a thumbnail and matching
embed border. Desktop notifications use bundled images: image data on Linux, an
attachment on macOS, and a local logo override on Windows. The operating system
controls how desktop images appear; macOS may show the attachment in the expanded
alert while retaining the green Ding app icon.

Warning watches and log events can supply `severity`, `level`, or `log.level` in
their projected fields. `warn` and `warning` select yellow; error and critical
levels select red. Firing events default to red. Recovery events select green
even if retained fields still describe an earlier error. Source recovery means
observations resumed; a condition incident may still be open.

This patch contains the notification changes on top of 0.15.2. It does not change
the database schema. Previously queued notifications retain their original payload.
The website images are published before the runtime rollout.

For Homebrew installations:

```sh
ding service stop
brew update
brew upgrade ding-labs/tap/ding
ding setup
```

Homebrew owns updates. The macOS helper remains ad-hoc signed for this distribution;
this release does not publish a notarized installer or enable standalone automatic
updates. Existing watch data and notification permissions are retained.
