# Ding 0.15.1

This patch fixes a macOS notification-helper crash that was incorrectly reported
as a permission denial, and brings the local demonstration into Ding Console.

```sh
ding service stop
brew update
brew upgrade ding-labs/tap/ding
ding setup
```

- **Try a one-minute demo** from Watches or first-watch setup. A real temporary
  HTTP endpoint moves through healthy, failing and recovered states; the Console
  displays the recorded events. Desktop alerts are optional. Closing the dialog
  cancels the demo and removes its temporary state.
- **Set up notifications** in System or first-watch setup. The guided dialog
  explains the permission prompt, opens macOS notification settings, checks
  permission status and lets you retry. First-watch setup also offers Console-only
  delivery while troubleshooting.
- `ding notify status --json` distinguishes authorization from alert presentation.
  `ding notify settings` opens notification settings on the Mac running Ding.
- Native macOS permission callbacks no longer inherit the main actor incorrectly.
  Helper failure, denied permission and a pending permission response produce
  different guidance.

If Ding is absent from System Settings → Notifications, send a test notification
first, respond to its permission prompt, then reopen Settings. Permission being
enabled does not prove a banner was visible; check Focus and confirm the test.

Existing watch data and schema 5 are unchanged. The Homebrew package still includes
the Console, native helper and Go MCP adapter; no account or language runtime is
required. This release does not publish Ding Cloud or a marketplace listing.
