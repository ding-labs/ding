# Ding 0.15.0

Ding now runs persistent local watches, with a browser Console, background startup,
native notifications and an MCP adapter built into the same installation.

```sh
brew install ding-labs/tap/ding
ding setup
```

Accept background startup, choose **Create your first watch**, enter your health
endpoint, and test a notification. No Ding account, language runtime, model key or
source checkout is needed. The machine must stay awake and connected.

## What is included

- HTTP, local command and JSON push sources; comparisons, numeric windows,
  consecutive failures and recoveries, changed values, missing data and new events.
- SQLite persistence, retained event evidence, durable delivery retries, offline
  replay, verified backups and private credential references.
- Console onboarding, watch management, event and delivery inspection, manifest
  editing and live status. `ding ui` reopens it.
- User background services, lifecycle commands and clear local status.
- Desktop alerts, Slack, Discord and webhooks. macOS includes the native
  notification and Keychain helper alongside the executable.
- The official Go MCP SDK adapter: `ding mcp setup` pairs a local model client
  using explicit, revocable grants. Claude Desktop and Claude Code can connect
  through stdio; ChatGPT still needs a supported remote connection.

## Distribution and boundaries

This release ships Homebrew archives for macOS 13+ and Linux, on ARM64 and x86-64.
Archives are built and tested on their native operating system and architecture;
the tap pins their SHA-256 hashes. Mac helpers are ad-hoc signed. This Homebrew
release is not an Apple-notarized `.pkg` or a Windows installer; those distribution
routes remain under qualification. No Gatekeeper override is required by the
Homebrew instructions. OS notification permission and visibility must be checked
on your own desktop.

Homebrew owns updates: stop Ding, run `brew update && brew upgrade ding-labs/tap/ding`,
then run `ding setup` again. Signed standalone automatic-update channels are not
published by this release. Uninstalling the service retains your watch data.

This replaces the old job-wrapper CLI. Existing legacy configurations are not
automatically activated; use `ding migrate` to review a conversion if needed.
The new watch runtime stores schema 5; do not open its state with an older binary.

Cloud hosting and marketplace packages are included in the source tree for
operators and integration development. There is no public Ding Cloud service or
approved marketplace listing in this release. Local monitoring is complete without
an account or a model client.
