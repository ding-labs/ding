From output to understanding

Start where
your software runs.

01 / Deploying

Keep a service in view.

Follow new log lines while you deploy. Watch the volume and severity of arriving records, then freeze the display to review recent errors.

tell-tail service.log --window 10
02 / Debugging

Watch a worker’s output.

Pipe stdout and stderr straight into a dashboard. Unbuffered output helps records arrive as the process writes them.

python3 -u worker.py 2>&1 | tell-tail
03 / Reviewing

Count a completed capture.

Scan a saved file for totals and severity counts. A fast scan measures processing throughput, rather than the original event rate.

tell-tail capture.ndjson --once

Install once.
Bring your own logs.

Native downloads support Apple Silicon on macOS 14+ and Linux on x86_64 or ARM64. The browser dashboard is built into the binary.

brew install ding-labs/tap/tell-tail
Cargo Requires Rust 1.88 or later
cargo install tell-tail --version {{tellTailVersion}} --locked

No log file handy?

Three lines.
Your first report.

Paste this into your terminal after installing. The final report stays open in your browser until you press Ctrl+C.

printf 'INFO ready\nWARN upstream slow\nERROR upstream timeout\n' | tell-tail --output web --open

Small, local, inspectable

Keep the view
close to the source.

Tell-Tail keeps counters, rolling statistics, and a bounded sample of recent errors in memory. Statistics reset on restart. It works offline, and webhook notifications are optional.

Log ratios describe the records received. They do not establish application health. For persistent watches, retained evidence, and durable notification retries, explore Ding.
