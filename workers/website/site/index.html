From the first observation to the last delivery attempt, Ding keeps the pieces connected.

  1. 01

    Observe

    Poll an HTTP endpoint, run an explicit command, or accept authenticated JSON.

    HTTP · command · push
  2. 02

    Evaluate

    Apply a declared condition. Keep incident state and recovery progress across restarts.

    One versioned manifest
  3. 03

    Record

    Commit the event and its evidence to local SQLite storage, with explicit retention limits.

    State + evidence + outbox
  4. 04

    Deliver

    Send notifications with durable retries. Inspect failures and deduplicate stable event IDs.

    Console · webhook · Slack · Discord

04 / Keep it yours

One daemon.
A durable memory.

Run Ding locally or on your own server. Its SQLite store keeps conditions, evidence, and pending notifications together.

A running daemon is required. Delivery is at least once; receivers should deduplicate event IDs. Retention and resource limits are explicit, and unknown input never silently clears an open incident.
